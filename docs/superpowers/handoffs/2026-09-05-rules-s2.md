## Three things S1 recorded specifically for S2

These are the traps S1 hit and deliberately left for this slice.

- **`map-vertices` `:record-reads` defaults to `T`.** `%unbound-claim-scan`
  walks a family with it. Inside a read-only `select` that is harmless;
  `run-rule` reads and writes in **one** transaction, so a walk there joins
  every scanned node to the read set and the run conflicts with any
  concurrent writer touching them. Decide explicitly: pass
  `:record-reads nil`, or refuse the walk inside `run-rule` the way a budget
  refuses it. Recorded on #331 with the argument for refusing.
- **Goal order is load-bearing and unenforced.** `(claim-producer ?c "p")`
  must precede the `claim/7` goal it feeds; the other order refuses, because
  `?c` is bound by then and `claim/7` takes its node route. `compile-rule`
  (§6) is the right place to reorder or reject — it already must reject
  other head shapes.
- **`graph-db.rules` is still an empty package**, and the first `def-rule`
  there must **not** import spacetime's `claim-producer`, `claim-relation`,
  `claim-standing` or `claim-rule-version` accessors. Those names collide
  with the functor names through `symbol-package`, and the guard's
  `(intern "CLAIM-PRODUCER" home)` would then resolve to the spacetime
  symbol and fail to find `CLAIM-PRODUCER/2`. The warning is in
  `rules/package.lisp`'s header; ruling R4 has the mechanism.

## Deviations from the spec that S2 inherits

Both are in the decision record with full reasoning. Kevin has seen them;
they are not open questions, but S2 must not quietly undo them.

- **The functors are homed in `graph-db`, not `graph-db.rules`** (spec §3
  names the package). `make-functor-symbol` resolves a goal head in the
  head's own package and then in `graph-db`, so a functor homed anywhere
  else is unreachable from a raw `select` in another package. The seven
  `name/arity` symbols are `graph-db` exports. The test package deliberately
  does not `:use #:graph-db`, so every goal in the suite exercises that
  fallback — if someone re-homes the file, the suite fails loudly.
- **The cost-unbounded rule is refined** (spec §4 says refuse, full stop): a
  nothing-bound goal is refused under a resource bound and walks the family
  without one. Invisible on the guarded surface, because
  `run-guarded-prolog` cannot be passed a NIL budget. Note the authority for
  this amendment is the S1 plan and handoff, both written by the same agent
  session that made the ruling — worth Kevin's eye if it ever matters.

      --eval '(push #p"<worktree>/" asdf:*central-registry*)' \
      --eval '(ql:quickload :graph-db/test :silent t)' \
      --eval '(asdf:test-system :graph-db/fast-test)'

- `graph-db/fast-test` is the main suite minus `*slow-suites*` — **4950
  checks in ~8 minutes** instead of 5370 in ~36. Use it while iterating.
  `asdf:test-system :graph-db` is still the full gate; run it before a push.
- Every suite in a **subprocess**, in the **foreground**, worktree first on
  `asdf:*central-registry*`. Never background a run: two background jobs
  were killed mid-run in the last session. For a long run use
  `setsid nohup … &` plus a watcher on the log.
- **Always target the `-test` system** and read the `Did N checks.` line.
  `asdf:test-system` on a non-test system is a silent no-op, and
  `fiveam:run!` on a suite skips the test system's `:perform`, leaving
  `*system-directory*` unbound so every test fails at `make-graph` for
  reasons unrelated to your change.

  measurably; a run that looks pathologically slow is usually contention,
  not a regression.

## Traps learned, beyond the S1 handoff's list

- **A merge into `experiment` never auto-closes an issue**, whatever the PR
  body says. Close by hand with the merge commit. This bit three times in
  one session.
- **Deleted tests keep suites green.** A scripted edit truncated a test file
  to EOF and removed a real regression test; all five suites stayed green,
  because a missing test only lowers a count nobody compares. Caught from
  the diffstat. After a scripted edit, run
  `git diff <base> -- <file> | grep -c '^-[^-]'` and expect 0 for an append.
- **FiveAM appends a name per registration**
  ([lispci/fiveam#94](https://github.com/lispci/fiveam/pull/94), a one-word
  fix open upstream since 2022), so recompiling in the same image leaves
  each suite listed twice in its parent. Harmless to execution — a
  test-case that already ran is skipped by its status — but any code that
  enumerates a suite's children must treat the list as a bag, not a set.
- **A non-vacuity argument can decay.** S1's first route test genuinely
  discriminated when written, then stopped once a later task changed the
  fallback, and nobody re-checked. When a test's justification depends on
  other code, say so in the test, and re-ablate after changing that code.
